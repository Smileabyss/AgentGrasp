# Agent 工作约定

## 高效执行与验证

以满足任务为准，按改动风险选择最小充分的检查，避免重复读取、扫描和等待。

- 开始前用 `git status --short` 和 `git diff --name-only` 确认工作区与本任务涉及的文件；不要把已有的无关改动纳入审查、格式化或验证。
- 未修改的文件无需为本任务计算哈希或重复验证。只有任务确实依赖其内容、缓存或完整性机制要求，或用户明确要求时，才读取或检查它们。
- 不默认执行全仓审查、全量测试、全量 lint、格式化或构建。文档改动检查差异即可；局部代码改动运行相关测试；只有公共接口、依赖、配置、构建流程或较大回归风险受影响时，才扩大检查范围。
- 已有检查结果仍适用于当前改动时，不重复运行；检查结果过期或相关输入变化时，再运行对应检查。
- 将相互独立的文件读取和检查并行处理；使用定向搜索，避免重复打开或扫描已读内容。
- 简单任务直接执行；多步任务只列出必要步骤和可验证的完成条件，达到条件后停止，不附加未请求的重构或检查。
- 不增加不必要的确认、审批或等待步骤；用户已授权的可逆操作直接完成。遇到实质歧义、不可逆操作或外部副作用时，再按需要确认，并遵守项目本身要求的检查与审批。
- 进度说明聚焦新发现、关键选择和阻塞点，省略机械操作的逐项播报。

## 抓取轨迹搜索与修正技能

本目录中的 agent 在用户要求搜索、改进或验证抓取轨迹时，按以下流程执行。目标是先利用已训练的轨迹记忆在 latent 空间提出候选，再由仿真判断真实抓取效果；连续搜索未成功时，利用当前最佳轨迹和对应视觉观测进行有依据的修正。

### 目标流程

1. **检查输入和运行条件**：确认数据集、Trajectory AE、latent Flow 检查点、物体索引/姿态、机器人配置、仿真任务配置及运行设备。读取相关模块和配置以确认轨迹维度、关节顺序、动作坐标系、物体姿态和成功判据。只使用仓库中实际存在的能力；若必需输入缺失，说明具体缺项并继续完成不依赖它的检查。
2. **记忆先验与 latent 搜索**：通过 `memory/` 的轨迹 AE 和 Flow 将 latent 候选解码为完整动作序列，在 latent 空间使用 CEM 搜索。每轮记录候选得分、碰撞、提升量和明确的成功标志；保存全局最佳候选及其 latent 向量、动作、物体姿态和评估指标。除非用户另有要求，“连续 5 轮”指 5 个完整 CEM iteration 均没有任何候选达到仿真成功判据；有成功候选时立即保留并结束失败回退流程。
3. **仿真验证与视觉采集**：候选必须在 Isaac Gym 中验证，不能仅凭 latent 得分、几何启发式或模型预测宣称成功。若前 5 轮未成功，重置到最佳候选所用的同一物体姿态，确定性地重放最佳轨迹，并为每个动作时刻采集/保存匹配的深度图（若相机接口不能提供深度，则明确记录限制，使用已有的点云/几何观测作为降级输入，不得称其为深度图）。记录相机内参、深度单位/有效值约定、时间步及相机位姿。
4. **从视觉证据修正动作**：把最佳轨迹作为蓝本，结合时间对齐的深度图序列，定位手与物体的相对位置、接触/遮挡变化及抓取后物体运动，据此提出幅度受限、平滑的腕部/末端和手指动作修正。优先复用 `agent/`、`memory/`、`perception/`、`tools/` 中已有模块；不得臆造仓库里不存在的“skill”或感知结果。明确区分观测事实与推断。
5. **坐标变换与运动学约束**：统一注明每个量的坐标系、单位和四元数顺序。使用已配置的相机到机器人基座变换将视觉目标转到基座/世界系；检查变换方向和组合顺序，避免把相机系数据直接当作世界系。利用所选机器人 URDF、关节名称和上下限进行正/逆运动学检查；如果项目已有 IK 工具则调用它，验证每个建议末端位姿的可达性，并以前一帧或最佳轨迹对应关节状态作为连续 IK 种子。保留手部通道顺序、EEF/wrist offset 和仿真动作格式。
6. **回放验证并迭代**：先检查轨迹形状、有限值、关节限位、四元数归一化、连续性和 IK 可达性，再在相同场景、初始姿态、控制器及成功判据下仿真回放修正轨迹。只有仿真成功标志成立才报告成功；否则比较修正前后指标，将表现更好的轨迹作为新的最佳蓝本，并在后续迭代中重新采集对应深度轨迹。达到用户指定的迭代/时间预算或明确的无改进停止条件后停止，报告最佳结果及尚未解决的问题。
7. **交付可复现结果**：汇报 CEM 轮次和是否触发回退、最佳轨迹来源、成功/失败判据、修正前后关键仿真指标、坐标变换/IK 检查结果，以及生成文件的路径。记录使用的检查点、场景和关键参数；不要将建议轨迹、IK 可达或静态接触推断表述成仿真成功。

### 本项目现状与接口约束

- 实施此流程时，先检查当前实际存在的入口和模块，勿假定特定脚本仍存在。将失败触发点放在每轮 CEM 评估之后：当连续 5 轮没有成功，选当前全局最佳候选执行视觉采集、修正、约束检查和仿真回验；回验失败后可更新最佳候选并继续闭环。需要避免中断 CEM 状态、错配物体重置姿态或将候选成功标志与全局标志混淆。
- 相机到基座的变换必须从配置/标定输入读取并记录。若运行配置没有该变换，不可假设“已知”就等于程序已加载；应指出缺失参数并在可用坐标系内继续静态分析。
- 调用当前聊天中的助手与运行中的搜索进程是两种集成方式。除非存在显式 IPC/API/回调通道，脚本不能自动把运行时数据发送到当前聊天；自动闭环应通过受控的 agent 子进程/API 实现，并将观测和输出结构化传递、校验后再送入仿真。

### 成功与安全边界

- 成功必须以环境定义的抓取成功判据为准，并报告判据的实际字段/阈值。
- 对 agent 输出做严格形状、数值、坐标系、关节限制和 IK 可达检查；非法或不可达结果直接拒绝并保留最佳已验证候选。
- 修正应围绕最佳轨迹做局部、平滑调整，不无依据地重写整段动作或更改场景、机器人、成功标准。
- 深度数据及坐标变换不能跨不同的相机姿态、物体姿态或仿真重置复用；每次回放应确保观测与轨迹时序对应。
- 运行外部 agent 前，只提供完成任务所需的观测、机器人描述和运动学工具；结果必须先验证再执行。
